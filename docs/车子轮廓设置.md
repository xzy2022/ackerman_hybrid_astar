# 车辆轮廓定义说明文档

### 1. 核心定义源

* **文件位置**: `src/config.py`
* **类名**: `VehicleConfig`
* **属性名**: `self.vehicle_outline`

### 2. 坐标系定义

车辆轮廓构建于**局部车辆坐标系**（Local Vehicle Coordinate System）：

* **原点 (Origin, 0, 0)**: 车辆**后轴中心** (Rear Axle Center)。
* **X 轴 (Longitudinal)**: 车辆纵向。正方向指向**车头**，负方向指向车尾。
* **Y 轴 (Lateral)**: 车辆横向。正负分别代表车身左右两侧（基于 `width / 2` 计算）。

### 3. 关键几何参数

轮廓由以下三个参数直接决定（默认值见 `src/config.py`）：

| 参数名 | 值 (m) | 物理含义 | 计算逻辑 |
| --- | --- | --- | --- |
| `front_hang` | 3.3 | **前悬** | 从**后轴中心**到车头最前端的距离。 |
| `rear_hang` | 1.0 | **后悬** | 从**后轴中心**到车尾最后端的距离。 |
| `width` | 2.0 | **车宽** | 车身总宽度，轮廓左右各取 `width / 2`。 |

> **注意**: `wheelbase` (轴距) 仅用于动力学计算和确定前轴位置，**不参与**车身外轮廓矩形的计算。

### 4. 轮廓生成逻辑

`self.vehicle_outline` 是一个 `2x5` 的 `numpy.ndarray`，定义了一个闭合矩形。顶点的生成顺序为**逆时针**（或顺时针，取决于左右定义，但在绘图中表现为闭合框），具体坐标如下：

1. **右前角**: `(front_hang, width / 2)`
2. **左前角**: `(front_hang, -width / 2)`
3. **左后角**: `(-rear_hang, -width / 2)`
4. **右后角**: `(-rear_hang, width / 2)`
5. **闭合点**: `(front_hang, width / 2)` (回到起点)

**代码实现 (`src/config.py`):**

```python
self.vehicle_outline = np.array([
    [self.front_hang, self.front_hang, -self.rear_hang, -self.rear_hang, self.front_hang],
    [self.width / 2, -self.width / 2, -self.width / 2, self.width / 2, self.width / 2]
])

```

### 5. 可视化验证

在 `test/test_visualize_config.py` 中，该轮廓被绘制用于验证：

* **黑色矩形框**: 即 `vehicle_outline` 定义的范围。
* **红色原点**: 明确标记在矩形内部偏后的位置（后轴中心），而非矩形几何中心。
* **尺寸标注**: 验证了车头长度为 `front_hang`，车尾长度为 `rear_hang`。

# 严格碰撞检测

### 1. 严格碰撞检测原理分析 (Strict Collision Detection Analysis)

该函数 `check_strict_path_collision` 的核心目的是抛弃简单的“圆覆盖模型”，转而使用**精确的车辆几何轮廓**与栅格地图进行求交测试。其工作流程如下：

1. **几何重构 (Geometry Reconstruction)**:
* **输入**: 车辆的局部轮廓 `vehicle_outline`（定义在局部坐标系）和当前路径点 `(x, y, yaw)`。
* **变换**: 将局部轮廓通过**旋转 (Rotation)** 和 **平移 (Translation)** 变换到世界坐标系中，得到车辆在当前时刻实际占据的多边形区域。


2. **空间过滤 (Broad Phase Optimization)**:
* 为了避免遍历整个地图，代码首先计算变换后车辆多边形的 **Bounding Box (AABB)**。
* 根据 Bounding Box 的最小/最大 `x, y` 索引，确定一个较小的矩形搜索区域（ROI）。


3. **精确判定 (Narrow Phase Check)**:
* **遍历 ROI**: 遍历该区域内的每一个栅格。
* **障碍物筛选**: 如果某栅格是障碍物 (`self.obstacle_map[ix][iy] == True`)。
* **点在多边形内测试 (Point-in-Polygon Test)**: 获取该障碍物栅格的**物理中心坐标**，使用 `matplotlib.path` 提供的算法（通常是射线法）判断该中心点是否位于车辆多边形内部。

### 2. 正确性验证 (Correctness Verification)

结合之前梳理的 `VehicleConfig` 中**车身轮廓的定义**，我们来逐项检查该代码的实现是否正确：

#### A. 坐标原点的一致性 (Origin Alignment) ✅ **正确**

* **轮廓定义**: 在 `src/config.py` 中，`vehicle_outline` 是基于 **后轴中心 (Rear Axle)** 为原点 `(0,0)` 定义的。
* **路径定义**: Hybrid A* 规划出的 `path_x, path_y` 也是追踪车辆 **后轴中心** 的轨迹（这是阿克曼运动学模型的标准做法）。
* **代码实现**:
```python
rotated_outline[0, :] += x  # x 是后轴中心的世界坐标
rotated_outline[1, :] += y  # y 是后轴中心的世界坐标

```


**结论**: 平移操作直接将局部原点（后轴）对齐到了世界坐标系的路径点上，**逻辑完全正确**。

#### C. 碰撞判定的严格性 (Strictness) ⚠️ **微小的精度说明**

* **实现方式**: 代码检查的是“障碍物栅格的**中心点**”是否在“车辆多边形”内。
```python
vehicle_path.contains_point((obs_x, obs_y))

```


* **潜在问题**: 障碍物在物理上是一个边长为 `resolution` 的方格，不仅仅是一个点。
* **漏检风险**: 如果车辆轮廓仅仅“切”到了障碍物格子的一个角，但没有覆盖到其中心点，该函数会返回 `False`（无碰撞）。


* **评价**: 尽管存在上述微小的离散化误差，但在栅格地图路径规划的语境下，这种处理是业界的通用做法。相比于“圆近似模型”，它已经极大地提高了检测精度，足以称为“Strict（严格）”检测。对于 Ground Truth Check 而言，该逻辑是**有效且合理**的。
